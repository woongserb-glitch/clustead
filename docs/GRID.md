# 아파트 생활권 격자 지도 (`/admin/grid`)

2026-08-05 작성, 2026-08-06 갱신. 커밋 `5e7902d` ~ `4065c7e`.

---

## 1. 목적

기존 Clustead 의 모든 baseline 은 **단지 중심 반경 집계**다. 단지 2,861개 각각에
대해 "반경 500m 안에 CCTV 몇 대" 같은 값을 미리 구워둔 구조라, 다음 질문에는
답할 수 없다.

- 단지가 없는 공간은 데이터에 **존재하지 않는다**. "서울 어디가 비어 있나"를 물을 방법이 없다.
- 단지보다 작은 해상도를 볼 수 없다. 같은 단지 안에서도 동/서쪽 환경이 다른데 한 점으로 뭉개진다.
- 두 인프라를 **공간적으로 겹쳐** 볼 수 없다. "학원은 많은데 CCTV는 적은 곳"이 어디인지 지도에 그릴 수 없다.

격자 지도는 **공간 자체를 질의 가능하게** 만든다. 서울을 100m 격자로 자르고
각 칸에 "이 칸에 산다면 생활권이 어떻게 되는가"를 계산해 넣는다.

**대상 사용자는 관리자·제한 인원**이다. 일반 방문자용 기능이 아니라 분석 도구다.
따라서 SEO·모바일 최적화 대상이 아니고, 원시 수치와 신뢰등급을 숨기지 않고
그대로 노출한다.

### 2-2. 격자 정의

| 항목 | 값 | 근거 |
|---|---|---|
| 셀 크기 | 100m 정사각 | 100m 셀 9개 = 300m 셀 1개로 **정확히** 포개져 확대별 집계가 합/평균만으로 끝난다. H3 는 부모-자식 육각형이 포개지지 않아 이 성질이 없고 C 확장 의존성이 붙는다 |
| 셀 ID | `(i, j)` = 원점 오프셋 | 원점 (37.40, 126.75). 파이썬·JS 양쪽에서 동일 계산, 라이브러리 불필요 |
| 표시 해상도 | 100 / 300 / 900m | 카카오 지도 level ≤3 / 4~5 / 6+ |
| 분석 범위 | 단지 반경 1km 내 셀 | 58,318칸 (핵심 500m 는 44,207칸) |

**범위 제한은 계산량 절감 효과가 거의 없다.** 실측상 500m 생활권이 서울 면적의
73%, 1km 가 96%다. 제한의 의미는 백분위 분모를 "아파트 생활권"으로 두는
통계적 정직성에 있다(산·하천을 분모에서 뺀다).

### 2-3. 세 가지 지표 — 집계 규칙이 서로 다르다

섞으면 조용히 틀린 숫자가 나가므로 `grid_service._MODE_TABLE` 에 고정돼 있다.

| 모드 | 뜻 | 셀 안 | 셀 간(거친 격자) |
|---|---|---|---|
| `coverage` | POI 가 **영향을 주는** 칸 (반경 내 개수) | SUM | **AVG** |
| `point` | POI 가 **위치한** 칸 | SUM | SUM |
| `nearest` | 최근접 POI 까지 거리(m) | MIN | MIN |

`coverage` 가 합산 불가인 이유: 같은 지하철역이 이웃한 여러 칸에 중복 계산되므로
9칸을 더하면 9배가 된다.

### 2-4. 반경 — 도달형과 작용형

반경의 의미가 두 갈래다.

- **도달형** = 내가 저기까지 갈 수 있나 → 사람이 이동하는 거리
- **작용형** = 이 지점에 효과가 미치나 → 시설의 물리적 작용 범위

기존 점수는 아파트라는 고정점에서 묻는 것이라 전부 도달형이다. 격자는 모든
칸이 질문 대상이라 작용형 레이어의 반경을 다시 잡아야 한다.

**CCTV 만 재정의했다(500m → 200m).** 카메라 유효 감시 범위는 수십 미터인데
500m 안의 146대(중앙값)가 이 칸을 지켜준다는 건 사실이 아니다. 200m 로 좁히면
CCTV 0 인 칸이 7% → 22% 가 되어 사각지대가 실제로 드러난다.
기존 단지 점수(`cctv_count_500m`)는 다른 질문이므로 500m 를 그대로 둔다.
**같은 장소에 두 숫자가 공존한다.**

> **반경은 `POI_META` 를 읽지 말 것.** 쓰이지 않는 잔재가 섞여 있다
> (`bus`=400 이지만 실제 500, `subway`=1500 이지만 실제 500).
> 검증법: 결과 페이지에서 "반경 N 내 …" 문구를 직접 확인.

별도 설계가 필요하다.

**제거(2026-08-06)**: 문화시설. `culture_filtered.csv` 는 시설이 아니라
**서울시 공공서비스예약 프로그램** 목록이었다. `service_name` 이 "2026년
미니솟대만들기(매주 일)" 같은 강좌이고, 628행 중 고유 장소는 355개라 한 장소가
최대 22번 중복 계산된다(천왕산 목공 체험장). 구성도 체험 353·키즈 186 이고
실제 문화 인프라(공연/전시)는 87건뿐이다. **모든 레이어와 상관이 0.10~0.29 로
낮았던 건 "독립적 신호"가 아니라 잘못 들어온 데이터였다.**

### 2-5-1. 레이어 추가 규칙 — 아파트 중심 수집 데이터는 넣으면 안 된다

**격자에 넣을 수 있는 조건: 아파트와 무관하게 수집된 전수 데이터일 것.**

기존 baseline 은 두 종류가 섞여 있다. 겉보기로는 구분되지 않는다.

| 수집 방식 | 카테고리 | 격자 사용 |
|---|---|---|
| **전수 원본을 읽어 단지 기준으로 집계** | 학원·CCTV·학교·병원·약국·버스·따릉이·충전기·문화·어린이보호구역·지하철 | 가능 |
| **단지 좌표를 중심으로 Kakao 검색해 수집** | **마트·카페·편의점** | **금지** |

후자는 **원본 자체가 아파트 반경 안에만 존재한다.** 아파트에서 먼 곳의 편의점은
애초에 수집된 적이 없다. 이걸 격자에 넣으면 아파트에서 떨어진 칸이 "편의점이
없는 곳"으로 그려지는데, 실제로는 **우리가 안 본 것**이다. 지도 전체가 조용히
틀린 그림이 된다.

**파일명도 믿지 말 것.** `data/cctv/national_cctv.csv` 는 이름과 달리 전국
데이터가 아니다. 관리기관이 서울특별시·서울시·금천구 셋뿐인 **서울 전용**
파일이다(59,750행). POI 수집 bbox 를 서울 밖 3km 까지 넓혔을 때 실제로 늘어난
것은 원본이 진짜로 넓은 레이어뿐이었다.

| 레이어 | bbox 확장 전 | 후 | 원본 실제 범위 |
|---|---|---|---|
| 학교 | 1,880 | **2,375** | 전국 (교육부) |
| 지하철 | 482 | **555** | 수도권 |
| 전기차 충전기 | 2,973 | 2,977 | 서울 + 경계 일부 |
| CCTV | 59,738 | 59,739 | **서울 전용** (이름과 무관) |
| 나머지 7종 | — | 변화 없음 | 서울 전용 |

**판별법** (`baseline_config.py` 의 `source` 라벨은 믿지 말 것 — `subway` 가
`kakao` 로 잘못 적혀 있다):

```bash
# 빌더가 Kakao API 를 호출하는가? 0 이면 전수 원본, 1 이상이면 아파트 중심 수집
grep -c "kakao\|requests\|urllib" scripts/build_<카테고리>_baseline.py
```

원본 파일의 컬럼도 증거가 된다. 행정 필드(학원지정번호·정원합계·수강료공개여부,
관리기관명, 역사_ID)가 있으면 공공 등록 대장이다. Kakao Local API 는 상호·주소·
카테고리만 돌려주므로 이런 필드가 나올 수 없다.

**중요**: 기존 Clustead 와 격자는 **같은 원본 파일**을 읽는다. baseline CSV 는
전수 데이터를 단지 기준으로 집계한 *결과*일 뿐이고, 격자는 그 중간 산물을
건너뛰고 원본 좌표로 직행한다. baseline 은 단지 2,861개 지점의 값만 가지고
있어 그 사이 공간을 복원할 수 없기 때문이다.

### 2-5-2. 레이어 중복 — 11개는 사실 4개 축이다

셀 단위 영향권의 스피어만 상관을 재보면 대부분의 레이어가 하나를 다르게 재고
있다.

| 쌍 | r |
|---|---|
| **병원 ↔ 약국** | **0.96** |
| 따릉이 ↔ 병원 | 0.73 |
| 버스 ↔ 병원 / 버스 ↔ 약국 | 0.72 |
| 학원 ↔ 병원 | 0.70 |
| CCTV ↔ 버스 | 0.67 |
| 지하철 ↔ 학교 | 0.14 |
| 문화 ↔ 지하철 | 0.10 |

병원↔약국은 **불균형 클러스터가 0개, 0km²** 다. 55개 쌍 중 유일하게 아무것도
나오지 않는다. 약국은 병원 옆에 있으니 당연하다.

**그런데 약국은 지울 게 아니라 제대로 쓸 문제였다.** 22시 이후 영업 444건(8%)을
서브타입으로 분리하니 상관이 갈라진다.

| | r |
|---|---|
| 병원 ↔ 약국 전체 | 0.96 |
| 병원 ↔ **야간약국** | **0.60** |
| 약국 전체 ↔ 야간약국 | 0.62 |

야간약국은 69% 칸이 0 이라 변별력도 충분하다. 산출도 달라진다 — 병원 대비
약국 전체 부족은 **0개 덩어리**지만, 병원 대비 **야간약국** 부족(50%p+)은
**30개 덩어리**가 나온다(구로·신길 9.71km²/단지180, 송파 가락·거여 6.03km²,
강남 도곡·역삼 5.11km²). 심야 의료 공백이라는 독립된 정책 질문이다.

(일요일 영업 `DUTYTIME7C` 는 5,510건 중 5,483건이 채워져 있어 기입 오류로 보고
쓰지 않는다.)

**충전기도 같은 경우였다.** 2,987곳 중 **1,094곳(37%)이 아파트 입주민 전용 등
이용제한**인데 전부 한 덩어리로 세고 있었다. 그 칸에 사는 사람이 실제로 쓸 수
없는 충전기를 "주변에 있음"으로 잡으면 공급을 그만큼 부풀린다.

| | 버스와 r | 따릉이와 r | 전체와 r | 0인 칸 | 중앙 |
|---|---|---|---|---|---|
| 전체 | 0.56 | 0.60 | 1.00 | 3% | 14 |
| 개방 | 0.56 | 0.58 | 0.89 | 6% | 9 |
| **급속(개방)** | **0.49** | **0.48** | **0.57** | **16%** | 3 |
| 이용제한 | 0.37 | 0.41 | 0.77 | — | — |

전체는 0인 칸이 3% 뿐이라 사실상 어디에나 있어 변별력이 없다. **급속(개방)**만
보면 16%가 0이 되고 "도시 밀도" 인자와의 상관도 0.56→0.49 로 떨어진다.
산출 예(버스 대비 급속 부족 50%p+): 관악 봉천·동작 사당 4.33km²/단지117,
성북 길음·정릉 2.29km², 노원 상계·중계 1.64km².

충전소 단위 레코드라 한 곳에 제한·개방이 섞인 경우가 198곳 있다. 개방분이
하나라도 있으면 개방으로 본다.

**따릉이는 재료가 없다.** 원본에 대여소ID·주소·좌표만 있고 거치대 수가 없어
나눌 축이 없다. 좌표가 `0.000000` 인 77건(2.2%)은 자동 제외된다.

**교훈: "상관이 높다 = 지운다"가 아니다.** 세 갈래를 구분해야 한다.

| 증상 | 원인 | 조치 | 사례 |
|---|---|---|---|
| 상관 높음 | 쓰는 방식 | 서브타입 분리 | 약국(야간), 충전기(급속·개방) |
| 상관 낮음 | 데이터가 잘못 들어옴 | 제거 | 문화시설(프로그램 목록) |
| — | 나눌 재료가 없음 | 그대로 유지 | 따릉이 |

축으로 묶으면 이렇게 된다.

| 축 | 구성 | 근거 |
|---|---|---|
| 철도 접근성 | 지하철 | 유일 독립축 (타 레이어와 0.10~0.57) |
| 의료 | 병원 + 약국 | r=0.96, 불균형 0 |
| 교육·아동 | 학교 + 어린이보호구역 | 상호 0.46, 타 레이어와 0.14~0.49 |
| 생활 밀도 | 버스·따릉이·CCTV·충전기 | 상호 0.5~0.7 |

문화시설은 모든 레이어와 상관이 0.10~0.29 로 낮지만, 이건 "독립적 신호"가
아니라 **628건뿐이라 생긴 노이즈**일 가능성이 크다. 1,500m 반경으로 억지로
92% 칸을 채우고 있다.

| `grid_zone` | 58,318 | 셀 메타 (in_core, apartment_count, gu, dong, boundary_distance_m) |
| `apartment` | 2,861 | 단지 좌표·주소·세대수·소속 셀 |
| `layer_meta` | 11 | 라벨·반경·신뢰등급·비고 |
| `grid_meta` | 8 | 원점·셀크기 등 |

`grid_zone.gu` 는 **행정경계 폴리곤 점-다각형 판정**으로 채운다(스캔라인
래스터화). 경계 밖(경기로 넘어간 생활권) 4,426칸만 최근접 단지 값으로 보완한다.

### 2-7. API (전부 `_require_admin()` 게이트, 미인가 시 404)

| 엔드포인트 | 용도 |
|---|---|
| `GET /admin/grid` | 지도 화면 |
| `GET /admin/grid/cells` | 뷰포트 격자값 — `bbox`/`layer`/`mode`/`factor`/`subtype`/`core`/`per_hh` |
| `GET /admin/grid/compare` | 두 레이어 백분위 차 — `layer`/`layer2`/`subtype2` |
| `GET /admin/grid/clusters` | 인접 불균형 덩어리 — `threshold` |
| `GET /admin/grid/transit-gap` | **철도 소외 생활권** — `distance`/`bus` |
| `GET /admin/grid/boundaries` | 자치구 경계 폴리곤 + 라벨 |
| `GET /admin/grid/points` | 개별 시설 위치 |
| `GET /admin/grid/cell/<i>/<j>` | 셀 하나의 전 레이어 상세 |

`robots.txt` 에 이미 `Disallow: /admin/` 이 있어 추가 조치 없음.

### 2-8. 색상 스케일

기본은 **절대 스케일** — 서울 생활권 전체 분포의 p0~p100 경계 101개를 응답에
실어 보내고 클라이언트가 값→백분위로 색을 정한다.

- **팬(이동)에는 재계산되지 않는다.** 캐시 키가 뷰포트가 아니라 선택(레이어·모드·격자크기·서브타입)이다.
- **줌은 100/300/900m 경계를 넘을 때만 바뀐다.** 값 자체가 달라지기 때문이다(300m 값은 100m 9칸의 평균이라 극단값이 깎인다: p90 이 62 → 58).

0 인 칸을 분포에 채워 넣는 것이 중요하다. 테이블에 행이 없는 셀은 곧 값 0 인데,
빼고 계산하면 CCTV 처럼 22% 가 0 인 레이어의 백분위가 통째로 왜곡된다.

체크를 해제하면 **상대 스케일**(화면 안 최소~최대)로 바뀌며, 이동할 때마다
재조정된다. 좁은 지역의 미세한 차이를 볼 때만 쓴다.

### 2-9. 경계 영향 칸 (`boundary_distance_m`)

11개 레이어 중 9개는 원본이 서울에서 끊긴다. 반경이 경계를 넘는 칸은 그 바깥을
**"시설 0"으로 세는 셈**이라 과소집계된다. 값이 낮은 게 아니라 못 믿는 값이다.

레이어마다 반경이 달라(200~1500m) 플래그를 레이어별로 두면 11개가 되므로,
셀마다 **서울 행정경계까지의 거리** 하나만 저장하고 조회 시 각 레이어가 자기
반경과 비교한다(`distance < radius` 이면 영향 있음). 거리는 100m 격자 위
다중시작 BFS 로 구한다(셀마다 폴리곤 25,222 정점을 재면 15억 연산).

| 반경 | 영향 칸 | 비율 |
|---|---|---|
| 200m (CCTV) | 5,239 | 9% |
| 500m (버스·병원·약국·지하철·학교·따릉이) | 7,639 | 13% |
| 1000m (학원·충전기) | 11,819 | 20% |
| 1500m (문화) | 16,137 | 28% |

**처리 방식**

| 곳 | 동작 |
|---|---|
| 백분위 분모 (`get_scale`) | **제외**. 학원 58,318 → 46,499칸, CCTV → 53,079칸 |
| 클러스터 탐지 | **제외**. 한쪽 레이어만 과소집계되면 차이가 부풀려져 가짜 불균형 덩어리가 잡힌다 |
| 지도 (`query_cells`) | **지우지 않고 회색(투명도 0.22)+점선 테두리**로 표시. 상태창에 "회색 N칸은 반경이 서울 밖으로 나가 과소집계 — 통계에서 제외됨" |

클러스터에 실제로 영향이 있었다. 서초 잠원·반포 덩어리가 5.12 → 3.17km² 로
줄었는데, 서초구가 과천·성남과 접해 경계 영향분이 섞여 있었기 때문이다.

### 2-10. 세대수 정규화 (`?per_hh=1`)

시설 절대량만 보면 **"사람이 많으니 시설도 많다"와 구분되지 않는다.** 강남이
항상 빨간 건 발견이 아니다. 공급(시설)과 수요(세대)를 **같은 반경**에서 재야
비율이 성립하므로, 레이어 반경마다 그 반경 안의 세대수를 따로 집계해둔다
(`grid_household`, 212,916행).

세대수는 `k-전체세대수`(단지 2,859개 / 172만 세대, 보유율 2,860/2,861).
**새 데이터 수집이 없다.** 분모가 작으면 비율이 폭발하므로 200세대 미만 칸은
아예 제외한다(학원 스케일 분모 50,679 → 37,117칸).

정규화는 `_cell_value_sql` 안에 들어가 있어 **scale·cells·compare·clusters
전부에 자동 적용**된다.

**순위가 실제로 뒤집힌다** (구별 셀 중앙값):

| | 절대량 상위 | 1,000세대당 상위 |
|---|---|---|
| 병원 | 중구 44 · 강남 41 · 영등포 38 | **종로 34.3** · 중구 23.9 · **관악 15.3** |
| 학원 | 양천 338 · 강동 209 · 송파 197 | **종로 24.1** · 양천 22.6 · **광진 21.0** |

순위 변동: 용산 25→6위, 강북 24→5위, 종로 17→1위(병원) / 종로 24→1위,
관악 20→5위, **강남 5→15위**(학원).

강남이 학원 5위에서 15위로 내려간다. 학원이 많은 만큼 세대도 많기 때문이다.
**절대량 지도가 보여주던 건 상당 부분 "거주 규모"였다.**

두 모드는 다른 질문에 답한다. 어느 쪽이 옳은 게 아니다.

- 절대량 — "시설이 물리적으로 부족한 곳"
- 세대당 — "거주 규모에 비해 부족한 곳" (정책 언어)

## 3. 구동 방법

### 3-1. 격자 빌드 (데이터 갱신 후 1회)

```bash
python scripts/build_grid_index.py
```

약 37초, `data/grid.db` 118MB 생성. baseline CSV 와 원본 POI 가 갱신된 뒤에만
다시 돌리면 된다.

### 3-2. 로컬 실행

```bash
CLUSTEAD_TEMPLATE_RELOAD=1 python app.py
```

`CLUSTEAD_TEMPLATE_RELOAD=1` 은 템플릿 자동 리로드용(기본 꺼짐). 이걸 안 켜면
Jinja 가 템플릿을 프로세스 메모리에 캐시해 **수정이 재시작 전까지 반영되지 않는다.**

접속 URL 은 아래로 출력한다(토큰은 `.env` 의 `CLUSTEAD_ADMIN_TOKEN`).

```bash
python -c "from dotenv import load_dotenv; load_dotenv(); import os; print('http://127.0.0.1:5000/admin/grid?admin_token=' + os.getenv('CLUSTEAD_ADMIN_TOKEN',''))"
```

### 3-3. 화면 사용법

1. **레이어** 선택 (라디오). 서브타입이 있으면 하위 체크박스가 펼쳐진다.
2. **표시 모드** — 영향권 / 위치 / 최근접 거리 / 비교·불균형
3. **세대수 정규화** 체크 시 1,000세대당 값으로 바뀐다(2-10). 단위가 `/천세대` 로 표시된다.
4. **철도 소외 생활권** 패널에서 `찾기` → 세대수 순 구역 목록. 항목 클릭 시 지도가 그 범위로 이동한다.
5. **비교 모드**에서 두 번째 레이어를 고르면 백분위 차가 발산 색상으로 칠해진다. 아래 `찾기` 로 불균형 덩어리를 서울 전체에서 찾는다.
6. **칸 클릭** → 우측 플로팅 패널에 상세. 단지 목록이 위, 인프라 수치가 아래. 헤더를 잡아 이동, 우하단으로 크기조절.
7. 패널의 단지를 클릭하면 지도에서 강조되고 그 위치로 이동. 마커를 클릭하면 패널 행이 강조된다.
8. 커서를 올리면 그 자치구가 주황으로 강조되고 이름이 뜬다.
9. **회색 점선 칸**은 경계 영향 칸이다(2-9). 값이 낮은 게 아니라 못 믿는 칸이며 통계에서 빠져 있다.

## 4. 얻을 수 있는 데이터 예시

### 4-0. 철도 소외 생활권 — 주력 산출물

`/admin/grid/transit-gap?distance=800`

**격자가 찾아낸 가장 큰 구조다.** 지하철은 다른 모든 레이어와 상관이
0.10~0.57 인 유일한 독립축이고, 불균형 총면적 상위 10개 쌍이 전부 지하철
조합이었다(학교↔지하철 189km², 다음 순위 쌍의 5~8배). 나머지 레이어들은
서로 r=0.5~0.7 로 "도시 밀도" 하나를 다르게 재고 있을 뿐이다.

**정의: 버스는 되는데 철도가 안 되는 곳**

| 조건 | 기준 |
|---|---|
| 철도 소외 | 최근접 지하철역 800m 초과 (도보 10분, 조절 가능) |
| 생활권 성립 | 버스 영향권이 서울 상위 50% 이내 |

버스를 기준선으로 쓰는 게 핵심이다. 단순히 "역에서 멀다"로 잡으면 북한산·
개발제한구역이 잔뜩 걸린다. **버스는 촘촘한데 철도만 없는 곳**으로 좁히면
사람이 실제로 사는 곳만 남고, 그게 곧 대중교통 위계 불균형이다. 버스는
신뢰등급 `high`, 점유율 88% 라 기준선으로 적합하다.

**산출: 171,050세대 · 단지 280개 · 41.9km² · 35개 구역**

| 세대 | 단지 | 면적 | 역까지 중앙 | 위치 |
|---|---|---|---|---|
| **25,202** | 38 | 4.18km² | 1,081m | 강북 번동, 노원 월계동 |
| **19,914** | 32 | 2.78km² | 1,081m | 동대문 장안·답십리동 |
| **16,651** | 27 | 2.10km² | 1,000m | 도봉 방학·쌍문동 |
| 15,893 | 35 | 3.79km² | 1,233m | 양천 신정, 구로 고척동 |
| 15,030 | 21 | 4.35km² | 1,132m | 서대문 남가좌, 은평 응암동 |
| 13,109 | 21 | 5.83km² | 1,206m | 금천 시흥, 관악 신림동 |

| 임계값 | 구역 | 세대 | 면적 |
|---|---|---|---|
| 600m 초과 | 58 | 341,292 | 80.6km² |
| **800m 초과** | **35** | **171,050** | **41.9km²** |
| 1.5km 초과 | 7 | 17,055 | 4.8km² |

**면적이 아니라 세대수로 줄 세운다.** 정책 우선순위는 사람 수이고, 이렇게
하면 "인구가 많아서 그렇다"는 반론이 성립하지 않는다 — 세대수 자체를 세고
있기 때문이다. 세대는 셀에 **위치한** 단지 기준이라 중복 계산이 없다.

답할 수 있는 질문:
- "이 연장 노선이 커버하는 소외 세대는 몇인가"
- "우리 구에서 철도 접근성이 가장 나쁜 주거지는 어디이며 몇 세대인가"

## 5. 개선 필요 방향

### 5-1. 데이터

| 항목 | 내용 |
|---|---|
| **서울 경계 절단** (조치 완료, 한계는 잔존) | 9개 레이어의 원본이 서울에서 끊겨 반경이 경계를 넘는 칸은 과소집계된다. `grid_zone.boundary_distance_m`(셀 → 서울 행정경계 거리)로 표시하고 통계에서 제외한다 — 아래 2-9 참고. 근본 해결은 경기·인천 원본 확보뿐이며, 서울 서비스에 필요한지는 별도 판단 |
| **투영좌표 3종** | 소방·유흥·쇼핑이 빠져 있다. 파일마다 CRS 가 달라(EPSG 5174/5179 추정) 빌드 시점 1회성 변환 스크립트가 필요하다. 유흥은 **작용형**이라 반경 200~250m 로 잡고 값이 클수록 나쁜 쪽으로 부호를 뒤집어야 한다 |
| **광진구 CCTV** | 지주 단위 등록인데 카메라대수를 채우지 않아 서울 중앙값(3.01대/지주)으로 추정 삽입 중이다. 서울 열린데이터광장 통계로 교차검증 필요 |
| **어린이보호구역 형상** | 실제 보호구역은 도로를 따라 선형인데 점 중심 원(300m)으로 근사하고 있다 |
| **음식점** | 535,817건 / 205MB. 넣으려면 별도 설계 필요 |
| **동 경계** | `grid_zone.dong` 은 여전히 최근접 단지 기준이다. 구는 행정경계로 바꿨지만 동은 경계 데이터를 안 받았다 |

### 5-2. 지표

| 항목 | 내용 |
|---|---|
| ~~인구 정규화~~ | **완료** — 세대수 정규화(2-10). 다음 단계는 동별 **인구**(세대수는 규모만 알려주고 연령 구성을 모른다. 노인 비율이 높은 동의 의료 수요는 다르다) |
| **레이어 4축 압축** | 11개 레이어가 사실 4개 축이다(2-5-2 근거). 병원↔약국 r=0.96·불균형 0 이라 통합 후보, 문화시설은 628건에 상관 0.10~0.29 로 노이즈 의심 → 삭제 또는 포인트 전용. 선택지 11→4, 조합 55쌍→6쌍 |
| **시계열 스냅샷** | 월간 갱신 시 `grid.db` 를 날짜별로 보관하기만 하면 6개월 뒤 "인프라가 늘어난/줄어든 지역"이 나온다. **지금 안 쌓으면 소급 불가능**하고 비용은 거의 없다 |
| **회귀 잔차** | 백분위 차는 순위 기반이라 견고하지만, "학원 밀도를 감안했을 때 예상보다 CCTV 가 N대 적음"이라는 절대량 진술은 회귀 잔차라야 나온다 |
| **거리 지표 확대** | 현재 `nearest` 는 5종(지하철·학교·병원·약국·어린이보호구역)뿐이다. 공원·종합병원·응급실도 개수보다 거리가 체감에 가깝다 |
| **시간 축** | 전부 현재 스냅샷이다. 갱신 이력을 쌓으면 "이 지역 인프라가 늘었나 줄었나"를 볼 수 있다 |

### 5-3. 화면·운영

| 항목 | 내용 |
|---|---|
| **클러스터 윤곽** | 현재 클릭 시 bounding box 점선이라 ㄱ자·길쭉한 덩어리는 실제보다 크게 보인다. 실제 셀 윤곽을 그리려면 셀 수백~수천 개를 그려야 한다 |

### 5-4. 아직 검증하지 못한 것

개발 환경(샌드박스)이 외부 네트워크를 차단해 **Kakao 지도 SDK 가 로드되지 않는다.**
따라서 다음은 데이터·로직만 검증했고 실제 렌더링은 사용자 확인에 의존했다.

- 격자 사각형·경계선·마커가 지도 위에 그려지는 모양
- 색상 대비(발산 색상의 회색 중립 구간이 배경과 섞이는지)
- 마커 33개가 한 화면에 뜰 때 격자를 가리는지

## 6. 작업 중 발견해 고친 결함

격자 작업과 **무관하게 이미 존재하던** 문제들이다.

| 결함 | 영향 | 커밋 |
|---|---|---|
| **CCTV 자치구별 등록단위 차이** | 5개 구는 행=카메라, 19개 구는 행=지주로 등록해 구별 순위가 실제 밀도가 아니라 등록 방식을 반영했다. 도봉 4→18위, 서초 5→20위, 용산 10→3위로 순위가 뒤집힘. **라이브 안전 점수 결함** | `fe1bfc7` |
| SQLite 연결 누수 | `with sqlite3.connect(...)` 는 트랜잭션 컨텍스트일 뿐 연결을 닫지 않아 요청마다 쌓였다 | `6ccd6e1` |
| 캐시 변수 섀도잉 | 캐시 키 `key` 를 BFS 루프가 셀 좌표로 덮어써 조회가 항상 빗나갔다. 2319ms → 1ms | `6ccd6e1` |
| 셀 집계 2단계 미분리 | `AVG(count)` 가 한 셀 안의 서브타입 행을 평균내 부분집합이 전체보다 커지는 모순 | `a67cf70` |
| 내부 필드 HTML 유출 | 계산용 `camera_weight` 가 마커 JSON 에 실려 단지당 +1.5KB | `fe1bfc7` |
| 반경 오독 | `POI_META` 의 잔재값을 읽어 버스·지하철·병원·약국 반경이 틀림 | `5e7902d`, `a870fcf` |

**미수정으로 남긴 것**: `baseline_config.py` 의 `subway.source` 가 `"kakao"` 로
잘못 적혀 있다. 실제 빌더(`build_subway_baseline.py`)는 Kakao 를 호출하지 않고
`data/subway/subway_station_master.csv`(수도권 전철 역사 마스터 784행, 39개
노선) 를 읽는다. 격자와 기존 baseline 이 같은 파일을 쓴다. 라벨만 틀린 것이라
격자 동작에는 영향이 없어 이번 범위에서 손대지 않았다.
