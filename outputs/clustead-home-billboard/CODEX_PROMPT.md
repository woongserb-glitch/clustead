# Clustead 홈 "전광판" 개편 — Codex 작업 지시

## 목적
Clustead의 차별점은 "범용 AI(ChatGPT·Claude)가 답하지 못하는 서울 아파트·동네 생활 인프라 질문에 정확한 숫자로 답한다"는 것이다.
홈을 이 답들이 번갈아 크게 뜨는 **전광판**으로 바꾸고, 주제마다 고정 주소의 **순위 페이지**를 만들어 검색엔진과 AI 검색이 인용할 수 있게 한다.
현재 홈은 d3 그래프(JS 렌더링)라 크롤러가 읽을 글자와 링크가 거의 없다(2026-07 SEO 진단의 근본 원인).

## 참고 자료 (이 폴더: outputs/clustead-home-billboard/)
- `prototype.html` — Claude가 만든 시안(실제 2026년 9월 데이터). 사용자 확인 완료. 같은 시안: https://claude.ai/artifact/QPVvE2tWfFu7WR2mQzKuW2
- `compute_home_preview.py` — 시안의 모든 숫자를 재현하는 스크립트(레포 data/ 읽기 전용). 각 순위의 정의가 코드에 있다. **이 정의를 바꾸지 말 것.**
- `home_preview.json` — 위 스크립트 출력.

## 사용자가 확정한 요구사항
1. 홈 상단 전광판: 주제별 1위가 몇 초마다 바뀌며 크게 표시된다(하나만 고정 노출하지 않음). 마우스를 올리면 멈추고, 막대로 주제를 고를 수 있다. `prefers-reduced-motion`이면 회전하지 않는다.
2. 주제 카드 TOP 5. 아파트가 아닌 **동네(동) 단위 주제도 포함**(예: 입시·수학·영어 학원이 가장 많은 동, 구별 1위 동).
3. **카드마다 "산정 기준" 버튼**: 마우스를 올리면(hover), 누르면(tap, 휴대폰), 키보드 포커스로 기준이 보인다. Esc로 닫는다.
   기준에는 반드시 다음을 적는다: 기준점(단지 대표 좌표), 반경(m), 개수 기준인지 최근접 기준인지, 동률 처리, 출처와 수집일.
4. 주제(시안 기준): 학원 최다 아파트(반경 1km) / 학원 최다 동 / 국민평형 10억 미만+역세권+학원가 / 지하철 노선 최다(500m) / 스세권 / 편세권(4사 합계) / 유흥시설 없는 1,000세대 이상 대단지 / 응급실 최다(1km) / 이번 달 바뀐 것(신규 단지, 배정초 변경) / 구별 학원 최다 동.

## 반드시 지킬 정확성 규칙 (시안 작업 중 확인된 것)
- 학원 종류별 개수(exam/math/english)는 빌더상 **반경 1km**다. 전체 학원 수는 500m·1km 두 가지.
- 84㎡ 가격은 `avg_trade_amount_84` = **2025.1~2026.9 계약 전용 80~90㎡ 매매 평균**이다. "최근 1년"이라고 쓰지 말 것. 조합 주제는 300세대 이상 조건이 있다(초소형 단지가 1위가 되는 문제를 막음).
- 의료의 `superior_hospital`은 **종합병원+상급종합병원**이다. "대학병원"이라고 쓰지 말고 "종합병원급"으로 쓸 것.
- "학군"이라는 단어 금지(학원 수는 학군의 질이 아님). "학원가·학원 밀집"으로 쓴다.
- 동 단위 학원 수는 학원 주소에 적힌 **법정동** 기준. 동을 못 찾은 약 2%(378곳)는 제외됨을 기준에 명시.
- 거리는 모두 직선거리(도보 아님). 실거래가는 신고 건 평균(호가 아님). 최신 월 거래는 신고 기한 30일 때문에 일부만 반영됨.
- 학구명에 "(적용시기: …)" 설명이 붙은 경우가 있으니 표시 전에 정리.

## 구현 방향
- **서버 렌더링(Jinja)으로 HTML에 숫자와 기준 문구가 들어가야 한다.** JS가 나중에 채우는 방식 금지(크롤러가 못 읽음). 전광판 회전만 JS로 한다. 산정 기준 팝오버의 내용도 HTML에 미리 들어 있고, 숨김만 CSS/JS로 한다.
- **요청마다 CSV를 읽거나 계산하지 말 것.** 운영 서버는 RAM 961MB이고 기동 시 이미 600MB 이상을 읽는다. 월간 데이터 갱신 때 `compute_home_preview.py`를 바탕으로 한 스크립트로 `data/derived/home_rankings.json` 같은 산출물을 만들고, 앱은 그 작은 JSON만 읽는다(기동 시 1회 또는 lru_cache). 이 파일을 `scripts/verify_deployed_data.py`의 배포 대상 목록에 추가하고 self-check가 통과하게 할 것.
- "이번 달 바뀐 것"은 직전 스냅샷과의 차이가 필요하다. 갱신 스크립트가 차이를 계산해 JSON에 **저장**하게 한다(다음 달에 이전 파일이 없어도 표시 가능하게).
- 주제별 순위 페이지: `/rankings/<slug>` (TOP 20~50, 산정 기준 본문 노출, 데이터 기준월, 각 단지 상세 링크). canonical, `<title>`/description, 구조화 데이터(ItemList JSON-LD), sitemap.xml 등록. 홈 카드의 "전체 보기"가 여기로 연결된다.
- 디자인: 브랜드 팔레트 Ink `#15243B`, Steel `#38495D`, Mist `#F4F2EC`, 보조 파랑 `#2563eb`, 워드마크 Jost(`static/vendor/jost/` 셀프호스트). 시안의 전광판(잉크 배경 + 노란 숫자) 톤을 유지. 라이트/다크 모두.
- 모바일(≤760px): 현재 폰은 홈 그래프 대신 Explore로 보낸다(clustead-mobile-optimization). 전광판 홈은 폰에도 적합하니 폰도 새 홈을 보게 할지 사용자 결정이 필요하다(아래 질문).

## 작업 범위와 금지 사항
- 브랜치: **main에서 새 브랜치 `feature/home-billboard`**. 원래 레포 폴더는 `feature/ai-search` 작업용이므로 브랜치를 바꾸지 말고 **별도 git worktree**에서 작업할 것(데이터 폴더는 gitignore이므로 worktree의 `data`는 원래 폴더 data로의 junction을 써도 됨. 이미 `C:/Users/hyr19/clustead-main`에 main worktree + junction 예시가 있음).
- 금지: 데이터 재빌드·원본 데이터 수정, 커밋 외 push, 서버 배포, Cloudflare 설정 변경.
- 기존 테스트 통과 + 새 테스트: 순위 JSON 스키마 검증, 홈과 순위 페이지가 200이고 기준 문구가 HTML에 포함됨, 요청 처리 중 CSV를 열지 않음(파일 열기 mock), 공유·쿼리 변종이 sitemap에 들어가지 않음.
- 골든마스터(`tests/snapshot_result.py check`)는 단지 상세 페이지 기준이므로 변하면 안 된다.

## 사용자 확인이 필요한 결정 (구현 전 README에 질문으로 정리)
1. 기존 d3 그래프 홈: 전광판 아래로 내릴지, `/graph` 같은 별도 메뉴로 뺄지.
2. 휴대폰도 새 홈을 볼지, 지금처럼 Explore로 보낼지.
3. 스세권·편세권(카카오 로컬 데이터) 순위 공개: 카카오 API 약관상 재가공·순위 공개 가능 여부 확인 전까지 **설정으로 끌 수 있게** 구현하고 기본값은 사용자 결정에 따른다.
4. 순위 페이지 주소 체계와 TOP N 개수.
